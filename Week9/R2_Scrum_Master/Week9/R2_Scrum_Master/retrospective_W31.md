The whole team was asked at the same time. Every role replied independently, which reduced waiting time while preserving individual status records.

### Dependency control
R3, R4 and R5 were checked directly. Their completion was confirmed before R8 proceeded.

### Evidence-based status
Members identified actual GitHub files and screens instead of only saying that work was complete.

### Multi-model resilience
R8 retained multiple model outputs and fallback evidence, showing that the system did not depend on one provider.

### Human accountability
R7 applied Human Score and retained responsibility for the final interpretation rather than accepting AI output automatically.

### Presentation readiness
The final team sync confirmed role order, evidence and handovers before Demo Day.

## What Could Be Improved

### Repository consistency
Some Week 9 role folders are nested or inconsistently named. Direct and consistent paths would make the final audit easier.

### File naming
The visible R8 synthesis filename uses W30 even though the content belongs to the W31 final sprint. Final filenames should match the release week.

### Earlier rehearsal
The full spoken run-through should occur earlier in the final week so presentation problems can be corrected sooner.

### Automated DoD validation
R2 still relies on manual checking. A pre-release audit script should verify files, paths, role evidence, calibration and the release tag before R9 seals the sprint.

## Main Learning Across Nine Sprints

The project moved from manually prepared market notes to a structured system with:

- role-based evidence;
- automated data collection;
- multi-LLM comparison;
- fallback handling;
- Human Score;
- release tags;
- cumulative calibration.

The strongest Scrum lesson was that work is not complete merely because a file exists. It must be visible, inspectable, usable by the next role and supported by evidence.

## One Specific Process Improvement

Create an automated pre-tag audit that fails when:

- a required role file is missing;
- a Week 9 filename still uses W30;
- R3, R4 or R5 is missing before R8;
- the final prediction or Human Score is missing;
- cumulative calibration is missing;
- R2 stand-up or retrospective evidence is missing;
- the required release tag format is incorrect.
